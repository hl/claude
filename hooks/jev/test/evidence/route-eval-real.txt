# route.sh on the real set — 2026-10-18/19, Jev jev-1.13.0 (review round 2)
#
# Set: every Agent tool_use in the local transcripts (~/.claude/projects/**, subagents/ included;
# scratch test sessions excluded) -> 1461 unique tasks (test/harvest.sh). Sample for labelling
# (test/label-batches.sh): all 31 tasks with a weak under_routed label + a per-tier sample by the
# tier that ran (haiku 120, sonnet 130, opus 150, fable 20) = 451 tasks. Labels: ONE opus agent,
# prompt in test/label-prompt.txt, blind to the model that ran: haiku 151, sonnet 186, opus 114.
# Task-level data stays local in ~/.claude/jev/eval/; only aggregates are committed.
#
# Anchoring (N15). 136 of 451 briefs (30%) carry a line naming a tier ("Model: haiku — ...":
# 62 haiku, 61 sonnet, 13 opus), and every one of them names the tier that actually ran. They are
# 71 of the 151 haiku labels (47%). The labeller agreed with that line in 126 of 136 (92.6%);
# where there is no such line, label and tier-that-ran agree in 205 of 293 (70%). route.sh now
# strips these lines (anchors.jq) before asking Jev, so every number below is on stripped text;
# the labels are what they are, so the unanchored subset (945 rows, 315 tasks) is the cleaner one.
#
# Policy: the security/blast-radius and non-trivial-review gate (0.7 -> opus) is a design choice
# and is not tuned. Swept: P(haiku), mechanical, ambiguity, P(opus), confidence. Under-routing is
# counted with every Jev value moved 0.1 toward the cheaper tier. Holdout: two folds split BY TASK
# (all runs of a task on one side). Rule for the shipped point: the most conservative value of each
# threshold over the folds (higher P(haiku) bar, lower P(opus) bar).
#
# Reproduce (local):
#   EVAL_RUNS=3 JEV_EVAL_SET=~/.claude/jev/eval/labelled.jsonl hooks/jev/test/route-eval.sh
#   JEV_TUNE_SPLIT=1 hooks/jev/test/tune.sh ~/.claude/jev/eval/results-<time>.jsonl

## Reading
- Zero under-routing on the shipped point: 0 of 342 opus rows lower, 0 of 558 sonnet rows to haiku,
  in both sessions, nominally and with every Jev value moved 0.1 toward the cheaper tier, and on the
  unanchored subset (0 of 306 opus, 0 of 399 sonnet). Each fold's test half under the shipped point:
  0 and 0 (also at the margin).
- The folds disagree. Session 1: fold 0 picked P(haiku) 0.55 / P(opus) 0.35 and its test half had 0
  under-routed; fold 1 picked 0.5 / 0.6 and under-routed 3 opus rows on its test half (18 at the
  margin). Session 2 the same shape (0.6 / 0.35 and 0.5 / 0.6). The opus guarantee rests on the
  conservative choice, and on one opus task with P(opus) 0.17-0.19 that only the 0.7 security gate
  (0.88) keeps on opus; the next lowest are 0.47 (security 0.75), 0.56 and 0.64.
- Over-routing is 48% overall and 43% on the unanchored subset. Stripping the anchors raised it (the
  labels kept the anchored answers, Jev no longer sees them) and so did the stricter bars: round 1
  (P(haiku) 0.5, P(opus) 0.4, unstripped text) over-routed 35%. Most of it is sonnet-labelled work
  going to opus (388 of 558 rows).
- Weak redo/escalate labels: route.sh picks a higher tier than the one that ran for 42 of 93 rows;
  33 of the 93 already ran on opus or fable.
- What actually ran under-routed 8 of 429 tasks (6 opus-labelled); Jev's raw choice under-routes 5 opus
  rows on stripped text.
